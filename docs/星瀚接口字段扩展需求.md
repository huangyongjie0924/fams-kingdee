# 星瀚资产卡接口字段扩展需求

> 提出方：固定资产台账系统（asset-mgr）
> 目标接口：`POST https://<your-kingdee-host>/ierp/kapi/v2/gcgs/fa/fa_asset_card/Select_AssetCard`
> 状态：待星瀚侧确认与排期

## 一、结论（一句话）

该接口的财务字段 **取不到资产原值 / 累计折旧 / 净值**，返回的永远是 0，
导致台账的「财务信息」无法与星瀚系统对齐。需要星瀚侧把真实取值补进接口返回。

## 二、现状证据

对全库 **227 张资产卡**做了全量拉取，结果如下（可直接复现，命令见第五节）：

| 字段 | 实测结果 |
|---|---|
| `finentry[].fin_originalval`（资产原值） | 227 张**全部**为 `0.0000000000` |
| `finentry[].fin_networth`（净值） | 227 张**全部**为 `0.0000000000` |
| `finentry` 本身 | 200 张返回 `[{...}]`，27 张返回**空数组** `[]` |
| `price` | 227 张全部为 `0.000000` |
| `assetamount`（数量） | 227 张**全部有值**，正常可用 ✅ |

即：`finentry` 这个子表**确实会被返回**（不是没查出来），但里面那两个字段的值恒为 0。

## 三、具体需求

### 需求 1：修正 `fin_originalval`、`fin_networth` 的取值（必须）

这两个字段**已经存在**，只是值不对。请让它们返回资产卡财务信息页签上的真实数字。

> **对台账侧的影响：无需改代码。** 台账已按这两个键名做映射，只要值修对，
> 下一次同步就会自动覆盖，两边立刻对齐。

### 需求 2：新增「累计折旧」字段（必须）

接口目前完全没有这个字段。请在 `finentry` 里增加，并**告知实际使用的键名**，
台账侧按你方回填的键名做映射。

建议命名（沿用现有 `fin_` 前缀 + 小写下划线的风格，仅供参考，以你方为准）：

```
fin_accumdep            或
fin_accumdepreciation
```

### 需求 3：`finentry` 的取值口径需要明确（待确认）

`finentry` 是数组，但**取值期间的口径没有文档**。请确认：

- 是取「当前会计期间」的财务信息，还是「最新一条」？
- 一张卡是否可能返回多条？如果会，台账按什么规则取（第一条 / 期间最大的那条）？

现状是每张卡最多一条，所以台账暂时取 `finentry[0]`。若将来会返回多条，
需要按你方确认的规则调整，**请务必在回复中说明**。

### 需求 4：净值是否由星瀚提供（待确认）

台账侧目前按 `净值 = 原值 − 累计折旧` 自行计算，与星瀚界面口径一致
（359265.08 − 44908.14 = 314356.94 ✅）。

如果星瀚能直接给出净值，我们更希望**以星瀚返回值为准**（避免口径差异）。
请确认：`fin_networth` 修好后返回的就是最终净值，还是需要台账自行相减？

## 四、精度与格式要求

- **金额类**（原值 / 累计折旧 / 净值）：按元返回，保留 2 位小数，
  例如 `359265.08`、`44908.14`、`314356.94`
- 请保持**数值类型**（不要返回字符串），并保留小数位字面量
  （现状 `assetamount` 返回的是 `194.5200000000` 这种 10 位小数字面量，很好，
  台账侧按 `DECIMAL` 处理不会丢精度）
- 空值请返回 `0` 或 `null` 并保持一致，**不要混用**

## 五、复现方式（供你方验证）

```bash
# 1. 取 token
curl -s -X POST "https://<your-kingdee-host>/ierp/kapi/oauth2/getToken" \
  -H 'Content-Type: application/json' \
  -d '{"client_id":"<client_id>","client_secret":"<secret>","username":"<user>","accountId":"<account_id>","nonce":"<16位hex>","timestamp":"<YYYY-MM-DD HH:MM:SS>","language":"zh_CN"}'

# 2. 查询资产卡（注意 assetname / billno 必须非空，但实测不参与过滤）
curl -s -X POST "https://<your-kingdee-host>/ierp/kapi/v2/gcgs/fa/fa_asset_card/Select_AssetCard" \
  -H 'Content-Type: application/json' -H "accessToken: <token>" \
  -H "Idempotency-Key: <16位hex>" \
  -d '{"data":{"assetname":"1","billno":"1","filter":""},"pageNo":1,"pageSize":500}'

# 3. 直接看原始字面量（不要用程序反序列化后再打印，精度信息会丢）
#    预期看到： "fin_originalval":0.0000000000
```

## 六、补充说明

- 该接口是当前租户**唯一开放**的资产卡 OpenAPI。
  标准路径 `/v2/fa/fa_asset_card/query` 等均返回
  `404 Cannot found OpenAPI(or disabled)`，因此无法通过换接口绕过。
- `data.filter` 参数实测**不生效**（传过滤条件仍返回全量），
  所以台账的增量同步每次实际拉的是全量（结果幂等正确，仅不省流量）。
  如需真正支持增量，也请一并评估。
- 需求 1、2 完成前，台账侧的处理方式是：**由台账人员按星瀚界面人工填写原值 / 累计折旧**
  （支持卡片表单逐个填写，也支持 Excel 批量导入），净值自动计算。
  同步不会覆盖人工填写的金额。这是临时方案，长期仍希望以接口为准。
