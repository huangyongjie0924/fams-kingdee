## 1. 问题现象

`huangyongjie` 账号登录后，走完报修三步（选择资产 → 描述问题 → 确认提交），
在第 3 步点「提交报修」**没有任何反应**：没有成功提示、没有错误提示、单据不产生。

用户原话：「我使用 huangyongjie 的账号进去无法提交报修」。

## 2. 根因

**不是账号问题 —— 所有角色、所有账号都提交不了。**

`web/src/views/repair/New.vue` 的 `submit()` 里有一句无条件的
`await formRef.value.validate()`。而 `9706150`（2026-09-28 全站界面改造 P5）
把报修页改成三步式时，把 `el-form` 放进了 `v-else-if="step === 2"` 分支：

```
<template v-if="step === 1">   …选择资产…
<template v-else-if="step === 2">  <el-form ref="formRef"> …  ← 表单在这里
<template v-else>              …确认提交…（第 3 步，表单已卸载）
```

到第 3 步时 `el-form` 已被卸载，`formRef.value` 变成 `null`
⇒ 抛 `TypeError: Cannot read properties of null (reading 'validate')`
⇒ 异常发生在 `submitting.value = true` **之前**，`try` 块都没进去
⇒ `POST /api/repairs` 从未发出。

而那句 `formRef.value.validate()` 是三步式**之前**（`f4403f9`，2026-09-20）就有的
旧代码 —— 当时表单常驻，引用永远有效；改三步式时没跟着调整。

**回归时间点**：`9706150` 之后上线即坏。生产库 `repair_order` 的最后一单停在
`2026-09-23`（`WX202609232021`），此后至今为零，与该提交上线时间吻合。

## 4. 修复

```diff
   if (submitting.value) return;
-  await formRef.value.validate();
+  // ⚠️ 这里不能无条件 formRef.value.validate()：表单住在 step===2 的分支里，
+  // 到第 3 步时 el-form 已被卸载，formRef 变成 null → 抛 TypeError。
+  // 校验在第 2 步 → 第 3 步的 toConfirm() 里已经做过，第 3 步是纯只读核对页、
+  // 没有任何可编辑项；保留这一句只是防御将来模板结构再变。
+  if (formRef.value) await formRef.value.validate();
   submitting.value = true;
```

**为什么改 `submit()` 而不是把校验搬走**：校验的归属本来就是
`toConfirm()`（第 2 步 → 第 3 步，表单还在，且它是唯一的编辑入口）。
第 3 步是只读核对页，没有任何可编辑项，提交时再校验一次是冗余的。
保留带守卫的调用是为了将来有人往第 3 步加可编辑字段时不静默漏校验。

**同仓库排查**：全仓只有两处 `.validate()` —— `New.vue`（本次）与
`asset/CardForm.vue:553`。后者的 `el-form` **不在任何条件分支内**，常驻挂载，
不存在同类问题。
