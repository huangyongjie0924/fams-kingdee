## ⚠️ 回滚必须带 SQL（重要）

**换回旧二进制时，必须同时执行 `deploy/migrations/20260924_multi_role_rollback.sql`。**

原因：新二进制已把 `role='viewer'` 就地改写成 `employee`，而旧二进制的 `api/scope.go` 是
`switch u.Role { case model.RoleViewer: … }` —— `employee` **匹配不到任何 case**，会落到函数末尾的
`return model.AssetScope{}, true`，即**不限范围 = 读全量资产台账**；同时权限位全部失效。
结果是「丢写权限 + 拿全量读权限」，与 2026-09-24 在新代码里拦下的空角色 fail-open 完全同型。

> 这正是当初保留 `role` 列（主角色）作为回滚兼容的原因之一，但**改名**这一步把兼容性抵消了 ——
> 所以回滚是「二进制 + SQL」两步，不是一步。
