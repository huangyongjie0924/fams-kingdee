## 一、改版前的问题

旧页面是「Element Plus 默认卡片 + 一条紫色渐变」：

```
background: linear-gradient(135deg, #5b6bc0 0%, #3a4a9f 100%);
```

| 问题 | 具体表现 |
|---|---|
| 无品牌表达 | 只有一个 `el-card` 和一行标题，看不出这是什么系统 |
| 色彩单调 | 全屏只有一组紫→深紫，没有层次、没有强调色 |

| 默认感 | 圆角、阴影、按钮全是 Element Plus 出厂值，与任何其他后台长得一样 |

## 二、风格定位：工业简约

不是「把颜色调深」，而是按工业设计的语汇重建：

| 语汇 | 落地方式 |
|---|---|
| 材质感 | 石墨黑面板 `#14171b` + 工程网格底纹（44px 方格，4.5% 白） |
| 信号色 | **单一**强调色 安全黄 `#f5b301`，只出现在需要被看见的地方 |
| 制图感 | 四角 crop marks（裁切角标）、等距立方体水印、等宽字体注记 |
| 铭牌感 | 方框内等距立方体标识 + `FAMS / ASSET LEDGER` 字距拉开 |
| 资产意象 | 条码装饰条（纯 CSS 重复渐变，零图片资源） |
| 硬边 | 圆角一律 `2px`；不使用投影、不使用玻璃拟态 |

**为什么强调色只用一种**：工业场景里颜色是功能性的（安全黄 = 警示/标识），
不是装饰性的。多加一种颜色就立刻变成「后台模板」，而不是「设备台账系统」。

| 断点 | 行为 | 实测 |
|---|---|---|
| ≥901px 且高 >620px | 双栏完整版 | 1440×900：778 / 662 分栏，无滚动 |
| ≥901px 且高 ≤780px | 双栏收紧纵向节奏（标题 34px、间距压缩） | 1366×640：`docScrollH == docClientH == 640`，无裁切 |
| ≤900px **或** 高 ≤620px | 隐藏品牌面板，改由 `.auth-head` 承担标识 | 390×844：`brand.display=none`、`authHead.display=flex`、单列 390px |

## 七、实现要点与踩坑

1. **按钮高度不吃 `--el-component-size-large`**
   Element Plus 把 `.el-button--large` 写死成 `{--el-button-size:40px;height:var(--el-button-size)}`，
   只改 `--el-component-size-large` 会让输入框 48px、按钮停在 40px。必须额外给 `--el-button-size: 48px`。
   （首轮截图实测 `inputHeight:48 / buttonHeight:40`，改后 48/48。）

2. **水印只做肌理不做图形**
   等距立方体水印首版 `opacity: .07`，会跟规格表抢注意力、像渲染残留。
   降到 `.035` 并加大出血后才是「底纹」。

3. **零图片资源**
   条码用 `repeating-linear-gradient`（34px 周期，8 段不等宽）、网格用两条 `linear-gradient`、
   标识与立方体用内联 SVG。**不新增任何静态文件**，`web/dist` 的产物清单结构不变。

4. **窄屏截图必须换 URL 整页重载**
   只改 viewport 尺寸不会重置页面状态，上一轮遗留的输入框焦点会带进下一张截图。
   截图脚本里用 `?r=<timestamp>` 强制真实重载，并把鼠标挪到 (5,5) 排除 hover 残留。

## 十二、企业标识接入（2026-09-24 追加）

### 素材来源与提取方式

原始素材是 `示例集团logo素材.ai`（1.6 MB，**PDF 1.5 兼容**格式，单页 A4 横版，
67 条矢量路径、**无内嵌位图**）。三个 logo 之间有一条竖线分隔，是标准的「集团 + 旗下品牌」锁定组合：

| Logo | 品牌色 | 尺寸(pt) | 路径数 | 产出 |
|---|---|---|---|---|
| 示例集团 GCGS | `#E16923` 橙（标记）+ `#585757` 灰（文字） | 162×148 | 20 | `gcgs.svg` 9.4 KB |
| 示例牌A BRAND_A | `#C91A1E` 红 | 111×152 | 15 | `triangle.svg` 7.2 KB |
| 示例牌B BRAND_B | `#154E8C` 蓝 | 127×147 | 31 | `diamond.svg` 10.5 KB |

**提取方式是「按绘图对象重建 SVG」，不是栅格化**，所以任意尺寸都清晰：

1. `page.get_drawings()` 取全部矢量对象；
2. 按「极窄且高」识别出分隔竖线，用它把左侧的集团 logo 切出来；
   右侧两个按**最大 x 间隙**再切一刀；
3. 每个 logo 按自己那几个对象的包围盒算 `viewBox`，逐段重建 `path d`；
4. 用 Chrome 渲染并与 MuPDF 位图（ground truth）**并排比对**确认一致。

### ⚠️ 重建 SVG 的关键坑：字形轮廓是多子路径，必须逐个子路径闭合

首版只在**整条 path 末尾**补了一个 `Z`，结果三个 logo 全部画错 ——
实心圆被挖错洞、字形变成空壳轮廓。

原因：字形的每个字是「外轮廓 + 内孔」**两个子路径**，闭合必须发生在**每个子路径末尾**，
否则 `fill-rule` 不生效。子路径边界靠「本段起点 ≠ 上一段终点」判定，遇到跳变就先补 `Z` 再开新 `M`。
修正后与 ground truth 逐像素一致。

> 也试过 `page.get_svg_image()`：渲染正确，但它把**整页路径**都塞进每个文件、靠 `clipPath` 裁剪，
> 而且三个文件共用 `id="clip_1"` —— **一旦内联到同一页面就会 id 冲突、裁剪失效、三个 logo 全露出来**。
> 所以弃用，改为自建 SVG（自建产物**不含任何 id**，内联也安全）。

### 设计决策：为什么放在浅色铭牌上

深色品牌面板上直接放 logo 会**破坏品牌规范**（原色必须落在足够对比的底色上）：

| Logo | 在石墨黑 `#14171b` 上的问题 |
|---|---|
| 示例集团 | 橙色标记可用，但**灰色文字对比度仅约 1.9:1**，几乎不可见 |
| 示例牌B | 深蓝 `#154E8C` 对比度不足，细节糊掉 |

**解法**：做一块**浅色铭牌**（纸白底 + 左侧 3px 信号黄边 + 2px 圆角）承载三个 logo。
这既解决了对比度，又正好是「设备铭牌」的工业语汇 —— 而且**还原了原始 `.ai` 的锁定组合排布**
（三个 logo + 中间分隔线）。

铭牌位于品牌面板左上角，logo 高度 62px；`.auth-head`（窄屏）单独用集团 logo，高度 52px。

### 为什么没有改动配色

集团品牌色是**橙 `#E16923`**，与设计里的信号黄 `#F5B301` 是同色系邻色，放在一起不冲突：
橙只在铭牌上出现（品牌区），黄只在功能元素上出现（聚焦环 / 按钮 hover / 状态点）。
**把强调色换成品牌橙**是可选项，只需改 `--signal` / `--signal-deep` 两个值。

### 资源落地

- `web/src/assets/logos/{gcgs,triangle,diamond}.svg` —— 改 logo 只需替换文件
- Vite 构建产出 `gcgs-CAPwYTKe.svg` / `triangle-Ah2UToh5.svg` / `diamond-BkVcfwjB.svg`，
  由 Login chunk 引用（`assets/*.svg`），随 `web/dist` 一起被 `//go:embed` 进二进制
- 用 `<img>` 而非内联：Login.vue 保持可读，logo 可独立替换、可被浏览器缓存
