## 0. 方案摘要

登录页已经完成「工业简约」改版，但内页仍是 Element Plus 默认观感。本方案把已落地的视觉语言扩展到全部 26 个视图，并把按模块堆叠的导航重组为按任务组织。

**定位：演进，不是推翻。** 保留现有信息密度、双端分叉与全部数据结构，只统一视觉语言、收敛导航层级、补齐移动端。

| 指标 | 现状 | 目标 |
|---|---|---|
| 视觉一致（同一套 token） | 1 / 26 视图 | 26 / 26 |
| 导航结构 | 12 项平铺、无分组 | 5 组、每组 ≤3 项 |
| 字号档位 | 9 个无 token 的值 | 8 档有语义的 token |
| 移动端一级导航 | 0（只有汉堡抽屉） | 底部标签栏 4 项 |
| 列表工具栏控件 | 12 个平铺 | 5 个 + 选中浮条 |
| 路由改动 | — | **0（深链全部保留）** |

**性价比最高的一步（P0）**：新增 `web/src/styles/tokens.css`（约 120 行）覆盖 Element Plus 主题变量。不碰任何页面组件，26 个视图同时从「默认蓝」变为「工业简约」。

## 1. 现状诊断

以下每条均来自真实源码读取，附文件与行号，可直接复核。

### 1.1 视觉断层：登录页与内页是两套语言

| 维度 | 登录页（已改版） | 内页（现状） |
|---|---|---|
| 强调色 | `#f5b301` 信号黄 | `#409eff` Element 默认蓝 |
| 结构色 | `#14171b` 石墨黑 | `#2b3245` 蓝紫灰（侧栏） |
| 圆角 | `2px` 硬边 | `8px`（EP 默认） |
| 分隔 | 1px 发丝线 + 四角 crop marks | 默认投影 + 8px 圆角卡片 |
| 字体角色 | 等宽字体承担技术注记 | 全站无等宽字体，编码/金额不对齐 |

证据：`Login.vue` 定义了完整的 `--ink/--steel-*/--signal` 令牌，但作用域限定在 `.login-page`；`Main.vue:69` 的 `.aside{background:#2b3245}` 与 `Main.vue:80` 的 `#232a3b` 是另一套完全独立的深色值。

### 1.2 导航按模块组织，且靠权限位隐式表达角色

`SideMenu.vue` 共 12 个一级项，全部平铺、无分组、仅两层。维修相关三项尤其易混：

| 菜单文案 | 权限位 | 去向 | 用户需要先知道什么 |
|---|---|---|---|
| 我的报修 | `repair.report` | `/repairs/mine` | 「我提交的单」 |
| 我的维修 | `repair.handle` | `/repairs?mine=1` | 「派给我处理的单」 |
| 维修管理 | `repair.dispatch` | `/repairs` | 「全量维修单」 |

三者语义是「我提交的 / 我处理的 / 全部」，文案只差一个字。用户必须先知道自己持有哪些角色才能推断该点哪个——把实现细节暴露给了用户。

> `Home.vue` 的 `repairEntry` computed 已经正确处理了这件事（按权限优先级决定标题与去向），但只在工作台生效，侧栏没跟上。

### 1.3 类型尺度失控

全站 `font-size` 出现 9 个不同值（13/14/15/16/18/20/22/24/26px），无 token、无层级语义。典型症状：`Main.vue:77` 品牌标题 15px、`Home.vue` 页面标题 22px、列表页标题 20px——同一层级元素在不同页面尺寸不同。

### 1.4 列表工具栏 12 个控件平铺，无主次

`asset/List.vue` 工具栏顺序：批量 · 新建 · 编辑 · 调整状态▾ · 删除 · 打印标签 · 导出 · 扫码 · 间隙 · 搜索框 · 高级搜索 · 列配置。

- 主操作「新建」排在第 2 位，被低频的「批量」压在前面。
- 「批量 / 编辑 / 删除」是**模式性动作**，未选中任何行时也常驻，点了才提示「请先选择」。
- 搜索框被挤在右侧、宽度受限，而检索是最高频动作。

违反 Hick 定律（选项越多决策越慢），也违反「主操作唯一且显眼」的通行做法。

### 1.5 移动端没有一级导航

`Main.vue:23` 移动端只有一个汉堡按钮打开 `el-drawer`：

- **两步才到扫码**。`SideMenu.vue:11` 的扫码项 `v-if="isMobile"`——产品已意识到移动端才需要扫码，却把它藏在抽屉里。
- **拇指够不到顶部**。汉堡按钮在左上角，单手竖握时是屏幕最难点到的位置之一。
- **没有「当前在哪」的持续提示**。抽屉关闭后无任何导航状态可见。

### 1.6 深色侧栏选中态缺失，品牌区与登录页断裂

- `SideMenu.vue:67` `.menu{border-right:none}`——Element 默认的选中态右侧指示条被去掉，只靠背景色变化区分，弱。
- `Main.vue:4` 品牌区是纯文字「固定资产台账」，无任何标识；登录页已接集团 logo 铭牌，两侧不连贯。
- 顶栏只有角色标签与用户下拉，无面包屑/页面标题——进入 `/master/category` 这类深层页面后无法回答「我在哪」。

### 1.7 哪些不该动（同样重要）

- **信息密度**：表格行高与字号适合企业台账场景。桌面一屏看到 12+ 行是正确的，不要为「呼吸感」改成 6 行。
- **双端有意分叉**：`List.vue` 桌面用表格+分页、窄屏用 `.m-card` 卡片列表，源码注释已说明「列配置对卡片没有意义」。分叉是对的，缺的是统一视觉语言。
- **对比度达标**：现有配色优于 WCAG AA。改造中任何新配色都必须复测，不能为「高级灰」把文字压到 4.5:1 以下。
- **工作台结构**：问候条 / 待我处理 / 概览卡 / 快捷入口四段清晰，`repairEntry` 逻辑正确。只统一视觉，不动结构。

## 2. 设计原则

### 原则 01 · 任务优先于模块
导航回答「我要做什么」，不回答「系统里有什么」。依据 **Jakob 定律**——用户大部分时间花在别的系统上，期望本系统遵循同样的心理模型。

### 原则 02 · 一屏一个主按钮
每屏最多一个实心黑按钮，其余降级为描边或纯文字。常驻的「批量」改为选中后浮出的操作条。依据 **Hick 定律**。

### 原则 03 · 工业语汇，克制表达
石墨黑 + 信号黄 + 2px 硬边 + 发丝线。去掉 8px 圆角与默认投影。这不是审美偏好：硬边与发丝线在高密度表格里比投影更少干扰，扫描效率更高。

### 原则 04 · 数据用等宽，标签用无衬线
资产编码、金额、日期、单据号一律等宽 + 右对齐。等宽让数字位对齐，一眼看出量级差异。

### 原则 05 · 移动端是一等公民
高频动作（扫码、报修）一步直达且落在拇指区。底部标签栏固定 4 项，其余走抽屉。只读会话不显示标签栏。依据 **Fitts 定律**。

### 贯穿全案的硬约束 · 只改呈现，不改契约
**本方案不改动任何路由 path 或 route name。** 云之家待办深链形如 `#/repairs/2019` 已推送到员工手机，改名即全部失效。

## 3. 信息架构与导航

### 3.1 导航分组：从「模块清单」到「任务地图」

```
日常         维修            盘点            数据            系统
├ 工作台     ├ 报修申请      ├ 盘点计划      ├ 批量导入      ├ 基础数据 ▾
└ 资产台账   └ 维修工单      └ 我的盘点      └ 金蝶同步      └ 用户管理
```

**分组可见性规则**：组内可见项为 0 时整组不渲染，否则低权限账号会看到一堆空组。

| 角色 | 日常 | 维修 | 盘点 | 数据 | 系统 |
|---|---|---|---|---|---|
| 管理员 admin | 工作台·资产台账 | 报修申请·维修工单 | 盘点计划·我的盘点 | 批量导入·金蝶同步 | 基础数据·用户管理 |
| 资产管理员 | 工作台·资产台账 | 报修申请·维修工单 | 盘点计划·我的盘点 | 批量导入 | 基础数据 |
| 维护人员 | 工作台·资产台账 | 维修工单 | — | — | — |
| 盘点员 | 工作台·资产台账 | 报修申请 | 我的盘点 | — | — |
| 部门负责人 | 工作台·资产台账 | 报修申请 | — | — | — |
| 员工 | 工作台·资产台账 | 报修申请·维修工单 | — | — | — |

### 3.2 维修入口收敛：一个入口，按角色定标题

把三项收敛为两项：一个创建动作，一个查看动作。查看动作的标题与去向由权限优先级决定。

| 权限条件（优先级从上到下） | 菜单标题 | 去向 | 页内分段切换 |
|---|---|---|---|
| `repair.dispatch \|\| repair.manage` | **维修工单** | `/repairs` | 全部 · 待我处理 · 我提交的 |
| `repair.handle` | **待我处理** | `/repairs?mine=1` | 待我处理 · 我提交的 |
| `repair.report`（兜底） | **我的报修单** | `/repairs/mine` | 我提交的 |

> **这段逻辑已经写好了。** `Home.vue` 的 `repairEntry` computed 实现了完全相同的优先级判断。落地时只需把它提到共享模块（如 `composables/useRepairEntry.ts`），侧栏与工作台共用同一份，避免两处漂移。

**为什么是「收敛 + 页内切换」而不是「保留三项」**：

- **多角色用户不再丢视图。** 一个账号同时持有 `asset_manager` 和 `maintainer` 时，旧方案按优先级只给一个入口，另一类视图被隐藏。改为页内分段切换后三个视图都在同一页可切换。
- **导航项数与角色解耦。** 侧栏项数不再随权限组合变化，视觉稳定，换角色后不需重新学习导航结构。
- **符合用户心理模型。** 用户想的是「看维修单」一件事，不是「我的维修」和「维修管理」两件事。

### 3.3 移动端底部标签栏

| 位置 | 标签 | 去向 | 显示条件 |
|---|---|---|---|
| 1 | 工作台 | `/` | 始终 |
| 2 | 资产 | `/assets` | 始终 |
| 3 | **扫码** | `/scan` | 始终（本轮最重要改动） |
| 4 | 维修 | 同 3.2 角色规则 | `repair.*` 任一 |

三条必须遵守的实现约束：

1. **只读会话不显示。** `auth.readonly`（云之家深链免登）为真时侧栏与抽屉都已隐藏，标签栏必须同样隐藏，否则出现「能点但点了 403」。
2. **主内容区要留底部空间。** 标签栏固定 52px + `env(safe-area-inset-bottom)`，`.main` 需相应增加 `padding-bottom`，否则列表最后一行被遮住。
3. **抽屉保留。** 标签栏只放 4 项高频，完整菜单仍在汉堡抽屉里——标签栏是补充不是替代，低权限账号也不会有空位。

> ⚠️ `useIsMobile` 定义是 `(max-width: 767px), (max-height: 520px)`。第二个条件是**高度**断点，用于兜住横屏手机。标签栏必须挂在同一个 `isMobile` 判断上，否则横竖屏切换会出现「有侧栏又没标签栏」的中间态。

## 4. 视觉系统

四类色彩角色分明：**石墨黑 = 结构**（侧栏、主按钮、标题），**信号黄 = 交互反馈**（聚焦环、选中指示条、hover），**钢灰 = 中性信息层级**，**语义色 = 状态**。

### 4.1 色彩令牌

```
结构色与中性阶
  --ink          #14171b   结构色 / 主文字
  --ink-2        #1c2127   悬浮态
  --steel-700    #3d454f   正文次级
  --steel-600    #5c6470   辅助文字
  --steel-500    #6b7480   说明文字
  --steel-400    #8d959f   占位符
  --steel-300    #c3c9d0   强边框
  --steel-200    #dde1e6   发丝线
  --steel-100    #eef1f4   表头 / 条纹
  --paper        #f6f7f9   页面底色
  --surface      #ffffff   卡片面

强调色与语义色
  --signal       #f5b301   交互反馈（唯一强调色）
  --signal-d     #cf9700   黄底上的文字
  --ok           #2f8f4e   成功 / 在用
  --warn         #c9781a   警告 / 借用
  --danger       #c0392b   危险 / 报废
  --info         #5c6470   中性信息 / 调拨中
```

> **语义色比 Element 默认值整体压暗。** EP 默认的 `#67c23a` / `#e6a23c` / `#f56c6c` 饱和度过高，与工业简约的克制基调冲突，在白色卡片上刺眼。压暗后的值在 `#fff` 上对比度全部超过 4.5:1，可直接用于文字与图标。落地时通过 `--el-color-success` 等变量覆盖，**不逐页改 class**。

### 4.2 类型尺度（9 档收敛为 8 档）

| Token | 值 | 用途 |
|---|---|---|
| `--t-32` | 32px | 工作台大数（等宽） |
| `--t-24` | 24px | 区块大标题 |
| `--t-20` | 20px | 页面标题（每视图 h1） |
| `--t-16` | 16px | 卡片标题 |
| `--t-14` | 14px | 正文基准（说明段落、表单标签） |
| `--t-13` | 13px | 表格内容、次级信息 |
| `--t-12` | 12px | 辅助文字、统计口径、时间 |
| `--t-11` | 11px | 表头、微标、单位 |

**字体族**：界面 `-apple-system, "PingFang SC", "Microsoft YaHei", "Segoe UI", sans-serif`；数据 `ui-monospace, "SFMono-Regular", Consolas, monospace`（`--u-mono`）。

**等宽字体适用范围**（本方案「专业感」提升最明显的一处）：资产编码 / 标签编号 / 维修单号、金额与数量（一律右对齐）、日期时间（`2026-09-24 14:07` 定宽成列）、工作台大数字。

### 4.3 间距 · 圆角 · 描边

- **间距**（4px 基准）：4/8 图标与文字、标签内边距；12/16 表单字段间距、卡片内边距；20/24 页面内边距、区块间距；32/48 区块分隔、空状态留白。
- **圆角**：卡片、输入框、按钮、标签、下拉面板**全部 2px**；仅头像与状态点用 `50%`。覆盖 `--el-border-radius-base` / `-small` / `-round` 三个变量即全站生效。
- **描边与投影**：默认 1px `#dde1e6` 发丝线，强调用 2px；投影只保留一种 `0 1px 3px rgba(20,23,27,.06)`，仅用于下拉、抽屉、悬浮操作条。**卡片不再用投影表达层级**——用发丝线 + 底色差。

### 4.4 状态色映射与 chip 组件

现状使用 Element 的 `el-tag` 实心标签。问题不在颜色映射（映射是对的），而在**实心色块在高密度表格里形成彩虹噪声**——一屏 12 行 × 6 种状态，视觉噪声盖过数据。

**改为「点 + 描边 chip」**：统一白底 + 1px 同色系描边 + 6px 状态点。色彩信息仍在，但退到背景层。

颜色语义与 `api/meta.ts` 的 `STATUS_TAG` 完全对齐，**只改视觉呈现，不改映射关系**：

| 资产状态 | meta.ts 原 type | 新 chip 变体 | 色值 |
|---|---|---|---|
| 闲置 | `success` | ok（绿点） | `#2f8f4e` |
| 在用 | `primary` | ink（黑点） | `#14171b` |
| 借用 | `warning` | warn（橙点） | `#c9781a` |
| 维修中 | `warning` | warn（橙点） | `#c9781a` |
| 调拨中 | `info` | inf（灰点） | `#5c6470` |
| 报废 | `danger` | bad（红点） | `#c0392b` |

维修状态（10 个）同样处理，标签文案沿用 `REPAIR_STATUS_LABELS` 现成映射：

| 状态 | chip | 状态 | chip |
|---|---|---|---|
| 待受理 | inf | 待确认 | **sig（信号黄，唯一）** |
| 已受理 | ink | 已完工 | ok |
| 待审批 | warn | 已驳回 | bad |
| 已派工 | ink | 已撤单 | inf |
| 维修中 | warn | 报废评估 | bad |

> **「待确认」单独用信号黄**——它是唯一一个**需要当前用户动手**的状态（发起人确认完工），用唯一的强调色把它从其余状态里拎出来，是刻意的视觉层级设计。

## 5. 组件规范

### 5.1 页面骨架

现状 `Main.vue:104` 是 `.main{padding:0}`，每个页面自己管内边距，导致页面间留白不一致。统一为：

```
.page           max-width 1180px（列表类 1400px）；padding 20px 24px 32px；margin 0 auto
  .page-head      标题 + 描述 + 右侧主操作；底部 1px 发丝线
  .page-toolbar   搜索 / 筛选 / 更多；sticky top 0，白底
  .page-body      表格或卡片列表
  .page-empty     统一空状态
```

**顶栏补面包屑**：`Main.vue` 顶栏目前只有角色标签与用户下拉。建议在左侧（移动端汉堡按钮之后）加面包屑（如 `基础数据 / 资产分类`），由 `route.matched` 或路由 meta 生成。解决 1.6 中「深层页面不知道自己在哪」的问题，且不增加任何导航层级。

### 5.2 按钮层级

| 层级 | 样式 | 用途 |
|---|---|---|
| primary | 黑实心 | 每屏最多 1 个——最重要动作 |
| default | 描边 | 次级动作，可多个 |
| text | 纯文字 | 表格行内、工具栏图标按钮 |
| danger | 红字红边 | 仅破坏性动作，必须二次确认 |

**hover 与 focus**：主按钮 hover **翻转为信号黄底黑字**（沿用登录页 `.submit` 行为，形成跨页面一致的动作反馈）。输入框 focus 用信号黄描边 + `0 0 0 3px rgba(245,179,1,.15)` 外环（登录页已验证的配方）。

### 5.3 列表工具栏重排

```
现状（12 项平铺）  批量 · 新建 · 编辑 · 调整状态▾ · 删除 · 打印标签 · 导出 · 扫码 · 搜索 · 高级搜索 · 列配置
方案（3 + 1 + 更多）  [新建资产] [导入]  [搜索…]  [筛选 2]  [更多▾]
```

- 「更多」收拢：打印标签 / 导出 / 列配置 / 扫码。
- **批量操作从常驻按钮改为选中浮条**：未选中不显示；选中后从表格底部浮出深色操作条（`已选 N 项 | 调整状态 | 打印标签 | 导出所选 | 全选本页 | 取消`）。同时解决工具栏降噪与「点了才提示请先选择」的挫败感。
- **筛选条件以可移除标签回显**在搜索框右侧（`生产一部 ×`），用户随时知道在看什么子集。这是现有 `.summary-bar` 提示「已启用 N 个筛选条件」的升级版——把数量变成具体条件。

### 5.4 表格规范

- **表头**：`--steel-100` 底 + 11px 大写字距 + `--steel-600` 文字
- **行高**：标准 44px，密集模式 40px
- **斑马纹取消**，改为 hover 整行 `--steel-100`
- **数字列右对齐 + 等宽**：金额、数量、编码
- **操作列固定右侧**，用纯文字按钮
- **选中行**：`rgba(245,179,1,.09)` 信号黄浅底

### 5.5 空状态与加载态

- **空状态**：复用与登录页呼应的**等距立方体线稿**（登录页水印同款），配一句说明 + 一个主操作（如「新建资产 / 清除筛选」）。
- **加载态**：表格用骨架屏（`--steel-100` 底 + 1.4s 脉冲），不用转圈。按钮内联加载用 14px 转圈 + 文字变「处理中…」。
- **关键**：报修提交、批量更新这类写操作，按钮必须置为 loading 且不可重复点击——这是当前 26 个视图里需要逐个核对的地方。

## 6. 核心页面设计稿要点

### 6.1 工作台（首页）
保留四段结构（问候 / 待我处理 / 概览 / 快捷入口），统一视觉并补「我的待办」直连。

- 侧栏「维修工单」带角标 3——把「待我处理」数量标在导航上，不进工作台就能看到。
- 问候条改为石墨黑底，成为页面视觉锚点，承载唯一的黄底主按钮「报修」。
- 待办卡左侧 3px 竖条承载语义色，0 值整体降为 `--steel-300`（沿用现有 `.todo-bar` 结构，只统一色值）。
- 数字全部等宽 + 右对齐；原值合计用 `¥12,480,300` 而非带小数，减少视觉噪声。
- 侧栏品牌区接入集团 logo：`gcgs.svg` 白色单色版 + 「固定资产台账 / FAMS」两行文字，与登录页铭牌呼应。

### 6.2 资产台账（列表）
改动最集中的一页：工具栏从 12 项降到 5 项，批量改浮条，状态改 chip。

- 主操作上移到页头右侧，与页面标题同一行——「一屏一个主按钮」的落点。
- 筛选条件以可移除标签回显。
- 表格行 hover 整行高亮，替代斑马纹。
- 窄屏（<768px）保留现有 `.m-card` 卡片列表，卡片改用同一套 chip 与等宽编码，并把「详情」变成整卡可点。

> ⚠️ **不要动的东西**：`List.vue` 的 `MANUAL_EXCLUDED_STATUSES` 逻辑（「维修中 / 调拨中」不可手动改状态，因为次日 00:00 星瀚同步会抹掉本地改动）必须原样保留。视觉改造不能顺手「优化」这条业务约束。

### 6.3 资产详情
现状是纵向长页，改为「左内容 + 右粘性操作栏」。

- 右侧操作栏粘性固定，滚动时始终可见。
- 删除类动作与常规动作之间加分隔线，物理隔离，降低误触。
- 财务信息区块明确标注「星瀚同步，本地不可改」——本项目已确认存在「人工维护」与「星瀚托管」两类字段，必须在界面上说清楚，否则用户会反复尝试编辑。
- 维修记录直接内嵌（状态 chip + 一句话摘要 + 日期），不用跳转。

### 6.4 报修流程
现状是单页长表单，改为三步式（选择资产 → 描述问题 → 确认提交）。

- **选资产优先给扫码**。真实场景是「人站在设备旁」，扫码比在下拉框里找编码快一个量级。三条入口按此排序：扫码 → 搜索编码 → 从我的资产列表选。
- 选中资产后以卡片形式固定展示，带状态 chip——随时确认「我报的是哪台」。
- 紧急程度用分段控件而非下拉（一般 / 紧急 / 停机），三项一眼可比。
- **提交按钮 loading 必须锁死**。报修提交会触发云之家待办推送（现已改为同步调用），网络慢时用户容易连点，产生重复单据。

### 6.5 扫码作业
保留现有三条降级路径（取景解码 / 拍照识别 / 手动输码）。

- 取景框用四角 crop marks + 信号黄扫描线，与登录页语汇一致。现有 `.frame` 已是对的方向，统一配色即可。
- 结果以左侧色条卡片反馈（绿=识别成功、灰=历史）；识别成功用信号黄闪一下再跳转，给用户「扫到了」的确认。
- **性能常数不动**：`SCAN_W=480` / `FRAME_MS=125`（约 8fps）/ `PHOTO_MAX=1000` 是为低端手机调过的，视觉改造不得调整。
- 新增「最近识别」列表：盘点场景下用户会连续扫几十台，能回看刚扫了什么可以显著降低重复劳动。

### 6.6 移动端
- **底部标签栏 52px + `env(safe-area-inset-bottom)`**，当前项用信号黄顶部 2px 指示条 + 图标染色。
- **扫码从「抽屉第 3 项」变成「标签栏第 3 格」**——从两步变一步，且落在拇指最舒适的位置。
- 卡片左侧 3px 竖条承载状态色，与桌面表格 chip 同色系，跨端语义一致。
- 列表页右上角保留「＋」直接新建；报修在有权限时用右下悬浮按钮（FAB）承载。
- ⚠️ **只读会话（`auth.readonly`）下标签栏整体隐藏**，与侧栏/抽屉同一判断。

### 7.2 关键技术实现：Element Plus 变量覆盖

本项目已有成功先例——登录页的 `.submit { --el-button-size: 48px }` 就是局部覆盖 EP 变量。全站层面只需把覆盖点提到 `:root`：

```css
:root {
  /* 结构色 —— 取代 Element 默认蓝 */
  --el-color-primary:        #14171b;
  --el-color-primary-light-3:#3d454f;
  --el-color-primary-light-5:#6b7480;
  --el-color-primary-light-7:#c3c9d0;
  --el-color-primary-light-8:#dde1e6;
  --el-color-primary-light-9:#eef1f4;
  --el-color-primary-dark-2: #000000;

  /* 语义色 —— 整体压暗，适配工业基调 */
  --el-color-success:#2f8f4e;  --el-color-warning:#c9781a;
  --el-color-danger: #c0392b;  --el-color-error:  #c0392b;
  --el-color-info:   #5c6470;

  /* 硬边与发丝线 */
  --el-border-radius-base:2px; --el-border-radius-small:2px;
  --el-border-radius-round:2px;
  --el-border-color:#dde1e6;   --el-border-color-light:#eef1f4;
  --el-border-color-lighter:#eef1f4;

  /* 文字层级 */
  --el-text-color-primary:#14171b;  --el-text-color-regular:#3d454f;
  --el-text-color-secondary:#6b7480; --el-text-color-placeholder:#8d959f;

  /* 投影只保留一档 */
  --el-box-shadow-light:0 1px 3px rgba(20,23,27,.06);
  --el-font-size-base:14px;
}
```

> ⚠️ **必须记住的 EP 陷阱**：`.el-button--large` 的高度是**硬编码**的（`--el-button-size:40px`），不读 `--el-component-size-large`。只覆盖上面这些变量时，输入框会变高而按钮不会——登录页已经踩过这个坑。若 P0 要统一表单控件高度，必须同时给按钮加 `--el-button-size`。

### 7.3 风险清单

| 风险 | 说明 | 应对 |
|---|---|---|
| **全站配色突变** | P0 一次性影响 26 个视图，可能有页面依赖「primary = 蓝色」的隐含假设（如自定义浅蓝底提示条）。 | 把 CDP 截图脚本扩展为逐路由截图，改动前后各跑一遍逐页比对。 |
| **深色侧栏对比度回退** | 侧栏底色从 `#2b3245` 改为 `#14171b` 后，次级文字 `#c8cddb` 对比度会变化，可能跌破 4.5:1。 | 必须复测。方法已建立：CDP 取 `getComputedStyle` 真实色，半透明前景先与背景合成再算比值。 |
| **权限表漂移** | 导航改造会碰 `auth.can()` 调用点。前端 `rolePermissions` 与后端 `model.rolePermissions` 必须逐项一致，历史真实漂移过一次（`asset_manager` 多出 `sync.manage`，按钮可见但点击 403）。 | 本次**不新增也不修改任何权限位**，只调整 `v-if` 的呈现位置。改完核对两个文件逐项相等。 |
| **只读会话露出写入口** | `auth.readonly = true` 时侧栏与抽屉已隐藏。新增标签栏若漏掉判断，会出现「点得下去但 403」。 | 标签栏、FAB、侧栏三处必须用**同一个** `!auth.readonly` 条件，建议抽成 computed 统一引用。 |
| **深链失效** | 云之家待办链接形如 `fams.example.com:8448/#/repairs/2019` 已推送到员工手机，路由改名即历史待办全部打不开。 | **本方案零路由改动**（见 3.4）。落地时逐条核对 path 与 route name 未变。 |
| **构建与部署** | 前端改动必须重新构建才生效（`web/dist` 被 `go:embed` 进二进制）；`npm run build` 会因批量删除守卫中止。 | 沿用已固化流程：先把 `web/dist` 移出仓库再构建；用首页 JS 文件名作版本指纹验收；对生产环境直接截图做最终确认。 |
| **顺手「优化」业务约束** | 视觉改造时容易把 `MANUAL_EXCLUDED_STATUSES` 当成多余的禁用逻辑删掉。次日星瀚同步会抹掉本地改动，用户会认为系统丢数据。 | P4/P5 改动列表页与详情页时，**业务逻辑一行不动**，只改呈现。 |
